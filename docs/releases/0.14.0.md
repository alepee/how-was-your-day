# How Was Your Day v0.14.0: Automatic summaries, and deleted sessions leave no audio behind

[![Downloads for this release](https://img.shields.io/github/downloads/alepee/how-was-your-day/v0.14.0/total.svg)](https://github.com/alepee/how-was-your-day/releases/v0.14.0)

Summaries can now start on their own once a session is ready, and a correction no longer throws an existing summary away ([#36](https://github.com/alepee/how-was-your-day/pull/36), built on [#14](https://github.com/alepee/how-was-your-day/pull/14) by [@RomainJeff](https://github.com/RomainJeff), thanks!). Deleting a session now deletes its audio, and the first launch removes the audio left by sessions deleted with an earlier version ([#26](https://github.com/alepee/how-was-your-day/pull/26)). Processing requests are queued instead of silently ignored, and edits made at the same time in the app and by an MCP client are no longer lost ([#27](https://github.com/alepee/how-was-your-day/pull/27) to [#32](https://github.com/alepee/how-was-your-day/pull/32)).

## 🎯 Highlights

- **Automatic summary** (opt-in): the summary starts on its own once the transcript is done and every voice is named, confirmed or ignored
- **Corrections keep the summary**: it is marked as made from an earlier transcript, and regenerating it stays your choice
- **Deleting a session deletes its audio**, and earlier leftovers are cleaned up on first launch
- **Transcription after a capture waits its turn** instead of having to be started by hand
- **A request that cannot start says why** instead of doing nothing
- **MCP changes show up within seconds** and no longer clash with edits made in the app

## 🔒 Security

### Deleting a session deletes its audio ([#26](https://github.com/alepee/how-was-your-day/pull/26))

Up to 0.13.0, deleting a session removed its notes and transcript but left its audio on disk. A session's audio files (both tracks), summary checkpoints, waveform cache and leftover job files are now removed with it. A file that cannot be removed is reported and retried on next launch.

The first launch of 0.14.0 also removes the files left by sessions deleted with an earlier version. Files younger than an hour are left alone, so a capture or processing that just started is never touched.

A session that is recording, transcribing or summarizing cannot be deleted until that ends or is cancelled. Voice fingerprints are unchanged: they belong to a person and are forgotten from **Settings › Audio and voice**.

## ✨ What's New

### Automatic summary ([#36](https://github.com/alepee/how-was-your-day/pull/36))

Turn on **Settings › Summary › Générer automatiquement** (off by default). Once a session is ready, meaning its transcript is complete and every voice is named, confirmed or ignored, its summary starts on its own after 10 seconds, so you can still undo a voice correction. A message announces each automatic summary and lets you cancel it.

- It makes one attempt per transcript version, waits for other processing to end, and never runs again once the session has a summary.
- Sessions that ended before you turned it on are never processed, so enabling it does not send your library to a provider. With a hosted provider, a ready session's transcript is sent without a further click.
- When the summary cannot run (provider not configured), nothing is sent and the line under **Generate** says why.
- Known limits: a refused attempt is not retried until the transcript changes, and a session left waiting when you quit is not picked up at the next launch.

The summary tab also says, in one line, when some voices are not identified yet, since the summary then refers to them generically.

### Corrections keep the summary

Correcting voices or the transcript, or transcribing again, no longer deletes the summary. The summary tab says the transcript has changed since the summary, and **Régénérer** refreshes it. Exports and MCP keep the summary and mark it `stale`; its source references may point to passages that no longer exist.

### Processing waits its turn

When a capture ends while other processing runs (a summary, a voice job, a model install), its transcription now waits and starts on its own. The transcript says it is waiting, and the wait can be cancelled.

A request that cannot start now (another one runs, the session has no audio, the examples are open) says why in a message. When a summary cannot be generated (no API key, no model, no local server address, no agent command), a line under **Generate** says why.

### MCP changes and app edits

Notes or voice names written by an MCP client show in the open app within a few seconds, even while you are editing or a processing runs, and are published to the export folder as soon as the app sees them.

An edit made in the app while an MCP client changed the same session is kept along with the client's change. When both touched the same part (the notes, for instance), the app keeps yours and says so. A session an MCP client deletes while the app holds unsaved edits on it is no longer created again: the edits are dropped and a message says so.

## 🐛 Bug Fixes

- The window no longer freezes for about a second when a meeting app takes the microphone during a capture: the capture now runs off the interface ([#33](https://github.com/alepee/how-was-your-day/pull/33)).
- The summary tab no longer calls every draft local: with a hosted provider it names the provider the transcript is sent to, with an ACP agent it says the draft comes from the agent.
- English messages about a missing API key or model no longer read "a Anthropic" or "a OpenAI".
- When the local data cannot be opened at launch, the app says so instead of staying silent.
- **Settings › Audio and voice** shows the voice separation models as installed only when they are on disk, instead of guessing from earlier sessions.
- Lifting an exclusion shows one message instead of two.
- A session being processed, voice recognition included, cannot be deleted until the processing ends or is cancelled.

## 🚧 Known limits

- Deleted notes and transcripts are removed from the database, but SQLite can keep their bytes in free pages of the database file until that space is reused.
- Retention is still not applied: sessions stay until you delete them.

## 🔧 Under the Hood

- The app's processing, settings, messages, session storage and export publication now sit behind interfaces with tested in-memory doubles, and a single coordinator owns heavy work ([#27](https://github.com/alepee/how-was-your-day/pull/27) to [#32](https://github.com/alepee/how-was-your-day/pull/32)).
- Audio capture runs behind an `AudioCapture` port off the main actor, one composition root chooses every adapter (the examples included), and audio files and API keys are reached through `AudioLocator` and `SecretVault` ([#33](https://github.com/alepee/how-was-your-day/pull/33) to [#35](https://github.com/alepee/how-was-your-day/pull/35)).

## 📦 Installation

Use **Check for Updates…** in the app menu, or:

```sh
brew update && brew upgrade --cask alepee/tap/how-was-your-day
```

Or download `HowWasYourDay.dmg` below (Apple Silicon, macOS 26 or later; signed and notarized).

No migration needed. Automatic summaries stay off until you turn them on. The first launch removes the audio of sessions you already deleted; your remaining sessions are untouched.

## 🐛 Bug Reports

If you encounter issues, please [open an issue](https://github.com/alepee/how-was-your-day/issues/new/choose) with:
- HWYD and macOS versions
- Your audio setup (built-in microphone, USB interface, Bluetooth headset) when recording is involved
- The exact error message

Do not attach recordings, transcripts or summaries of real conversations.
